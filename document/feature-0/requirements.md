# 勤怠管理アプリ — 要求仕様書

## 概要

従業員の出退勤打刻・勤務時間管理・申請承認を行う Web アプリケーション。
数万人規模のユーザ、複数拠点（タイムゾーン可変）に対応する。

---

## ユーザーロール

| ロール | 説明 |
|--------|------|
| 一般ユーザ | 打刻、勤務履歴確認、申請提出 |
| 承認者 | 一般ユーザの機能 + 部下の申請承認/却下 |
| アプリ管理者 | 全機能 + ユーザ管理、部署管理、会社カレンダー管理 |

- アプリ管理者・承認者も一般ユーザとして打刻・申請を行う
- 1部署に承認者は複数可（誰が承認してもよい）
- ユーザは複数部署に所属可能（主管部署を1つ持つ）
- 申請の承認者は主管部署の承認者
- 代理承認の仕組みは不要

---

## ユーザーストーリー

### US-1: 打刻

| ID | ストーリー |
|----|-----------|
| US-1.1 | 一般ユーザとして、「出勤」ボタンを押して出勤打刻したい。勤務開始時刻が記録される |
| US-1.2 | 一般ユーザとして、「退勤」ボタンを押して退勤打刻したい。勤務終了時刻が記録され、勤務時間が算出される |
| US-1.3 | 一般ユーザとして、「外出」「戻り」ボタンで中間打刻を記録したい。複数回の外出・戻りを記録できる |
| US-1.4 | 一般ユーザとして、打刻忘れがあった場合に翌日以降に打刻修正申請で修正したい |

**受け入れ基準:**
- 打刻時刻は出勤・退勤ともに分単位で切り捨て（秒は切り捨て。出勤/退勤で異なるルールは適用しない）
- 同日に複数回の出退勤は不可（1日1回の出勤・退勤のみ）
- 中間打刻は記録のみで勤務時間計算には影響しない
- 日をまたぐ勤務に対応する（例：22:00出勤〜翌6:00退勤）。ただし出勤日の勤務としてはカウントしない（暦日ごとに分割して計算）
- 出勤済みで退勤未打刻の場合、翌日以降は打刻修正申請が必須
- 打刻修正申請の遡及期限: 翌月第3営業日まで

### US-2: 勤務時間計算

| ID | ストーリー |
|----|-----------|
| US-2.1 | 一般ユーザとして、日ごとの実労働時間と残業時間を確認したい |
| US-2.2 | 一般ユーザとして、深夜勤務時間と休日出勤時間を区別して確認したい |

**受け入れ基準:**
- 実労働時間 = 退勤時刻 − 出勤時刻 − 休憩1時間（固定控除）
- 休憩1時間の固定控除は短時間勤務でも適用する（下限なし）
- 所定労働時間: 7.5時間（全ユーザ共通）
- 残業時間 = 実労働時間 − 7.5時間（超過分のみ）
- 半日休の日: 所定労働時間 3.75 時間。3.75 時間超過分が残業
- 深夜時間帯: 22:00〜翌5:00
- 休日: 土日 + 日本の祝日 + 会社カレンダーで設定した日
- 深夜かつ休日の時間帯: 深夜時間と休日出勤時間の両方にカウントする
- 賃金計算（割増率の適用）はシステム対象外。時間の記録・区分のみ
- タイムゾーンを含めた時間で計算する（拠点単位で設定）

### US-3: 勤務履歴

| ID | ストーリー |
|----|-----------|
| US-3.1 | 一般ユーザとして、月ごとの勤務履歴を一覧テーブルで確認したい |
| US-3.2 | 一般ユーザとして、当月の勤務日数・勤務時間合計・残業時間合計を確認したい |

**受け入れ基準:**
- 月次集計は各ユーザの所属拠点タイムゾーンのローカル日付基準
- 一覧テーブル表示（カレンダー表示は不要）

### US-4: 残業超過通知

| ID | ストーリー |
|----|-----------|
| US-4.1 | 一般ユーザとして、月の残業が30h/45h/60hを超過したときにアプリ内通知を受けたい |
| US-4.2 | 承認者として、部下の月残業が30h/45h/60hを超過したときにアプリ内通知を受けたい |

**受け入れ基準:**
- 月単位の累計残業時間で判定
- 通知先: 本人 + 主管部署の承認者
- アプリ内通知（メール通知なし）

### US-5: 打刻修正申請

| ID | ストーリー |
|----|-----------|
| US-5.1 | 一般ユーザとして、打刻ミスや打刻忘れを修正するための申請を提出したい |
| US-5.2 | 承認者として、部下の打刻修正申請を承認または却下したい |
| US-5.3 | 一般ユーザとして、申請中の打刻修正申請を取り下げたい |

**受け入れ基準:**
- 修正理由の記入は必須
- ステータス: 申請中 → 承認 or 却下 or 取り下げ
- 申請中ステータスの場合、申請者自身が取り下げ可能
- 却下時に承認者はコメント（却下理由）を入力する
- 却下後の再申請は可能（回数制限なし）
- 承認されたら勤怠記録に反映される
- 遡及期限: 翌月第3営業日まで

### US-6: 有給休暇申請

| ID | ストーリー |
|----|-----------|
| US-6.1 | 一般ユーザとして、有給休暇（全日休・半日休）を申請したい |
| US-6.2 | 一般ユーザとして、有給残日数を確認したい |
| US-6.3 | 承認者として、部下の有給休暇申請を承認または却下したい |
| US-6.4 | 一般ユーザとして、申請中の有給休暇申請を取り下げたい |

**受け入れ基準:**
- 種別: 全日休、半日休（午前/午後）
- 半日休の消化: 0.5 日
- ステータス: 申請中 → 承認 or 却下 or 取り下げ
- 申請中ステータスの場合、申請者自身が取り下げ可能
- 却下時にコメント入力
- 却下後の再申請は可能（回数制限なし）
- 事後申請（当日欠勤後に有給申請）可能
- 有給残日数がゼロの場合は申請不可
- 入社日基準で自動付与（労基法最低基準に従う）
- 前年度未消化分は1年間のみ繰越可能
- 承認時に残日数から消化

### US-7: 通知

| ID | ストーリー |
|----|-----------|
| US-7.1 | 承認者として、申請が届いたときにアプリ内通知を受けたい |
| US-7.2 | 一般ユーザとして、申請の承認/却下結果をアプリ内通知で受けたい |
| US-7.3 | ユーザとして、通知の未読/既読を管理したい |

**受け入れ基準:**
- 通知対象イベント: 残業超過(30h/45h/60h)、申請到着、承認結果、却下結果
- 未読/既読の管理あり
- アプリ内通知のみ（メール通知なし）

### US-8: ユーザ管理

| ID | ストーリー |
|----|-----------|
| US-8.1 | アプリ管理者として、ユーザを登録したい |
| US-8.2 | アプリ管理者として、ユーザ情報を更新したい |
| US-8.3 | アプリ管理者として、ユーザを無効化したい |

**受け入れ基準:**
- ユーザ登録: 名前、メールアドレス、ロール、所属部署（複数可）、主管部署、仮パスワード
- ロール変更（一般ユーザ↔承認者）可能。進行中の申請は変更後のロールに従う
- 主管部署を変更した場合、申請中（未承認）の申請は新部署に引き継ぎ
- 一度でも出退勤したユーザは物理削除不可 → 論理削除（無効化）
- 出退勤記録がないユーザは物理削除可能
- 無効化されたユーザはログイン不可

### US-9: 認証

| ID | ストーリー |
|----|-----------|
| US-9.1 | ユーザとして、メールアドレスとパスワードでログインしたい |
| US-9.2 | ユーザとして、ログアウトして認証情報をクリアしたい |
| US-9.3 | ユーザとして、初回ログイン時に仮パスワードを変更したい |
| US-9.4 | ユーザとして、パスワードを忘れた場合に管理者から仮パスワードを再発行してもらいたい |

**受け入れ基準:**
- 未認証ユーザのアクセスは認証エラー（ログイン画面へリダイレクト）
- パスワード要件: 8文字以上、英字・数字・記号を含む
- ログイン試行回数: 5回失敗で30分アカウントロック
- セッション有効期限: 最終操作から8時間
- 複数端末での同時ログイン: 許可
- 初回ログイン時に強制パスワード変更
- パスワードリセット: 管理者が仮パスワードを発行 → 次回ログイン時に変更強制

### US-10: 会社カレンダー管理

| ID | ストーリー |
|----|-----------|
| US-10.1 | アプリ管理者として、会社独自の休日をカレンダーに設定したい |

**受け入れ基準:**
- カレンダーは全社共通（拠点別の設定は不要）
- 土日 + 日本の祝日はデフォルトで休日
- 管理者が追加の休日（創立記念日など）を設定可能
- 休日設定は勤務時間計算（休日出勤判定）に使用される
- カレンダーは年度ごとに毎年再設定が必要（自動コピー機能なし）

### US-11: CSV エクスポート

| ID | ストーリー |
|----|-----------|
| US-11.1 | 一般ユーザとして、自分の勤務履歴を CSV で出力したい |
| US-11.2 | 承認者として、部下の月別集計を CSV で出力したい |
| US-11.3 | アプリ管理者として、全ユーザの勤務履歴・月別集計・ユーザ一覧を CSV で出力したい |

**受け入れ基準:**
- 対象データ: 勤務履歴、月別ユーザ別集計一覧、ユーザ一覧
- 権限: 一般=自分のみ、承認者=部下含む、管理者=全員分
- 対象期間の指定: 月単位
- 文字コード: UTF-8 BOM付き（Excel で開くことを想定）
- 出力項目: 勤務履歴に表示している項目 + ユーザ情報

### US-12: 拠点・タイムゾーン管理

| ID | ストーリー |
|----|-----------|
| US-12.1 | アプリ管理者として、拠点ごとにタイムゾーンを設定したい |

**受け入れ基準:**
- タイムゾーンは拠点単位で設定
- 拠点は部署に紐づく（ユーザは所属部署の拠点のタイムゾーンが適用される）
- 月次集計はユーザの拠点タイムゾーンのローカル日付基準
- ユーザが拠点異動した場合、過去の勤務記録は記録時点のタイムゾーンのまま保持する（遡及変更しない）

### US-13: 部署管理

| ID | ストーリー |
|----|-----------|
| US-13.1 | アプリ管理者として、部署を作成・編集・削除したい |

**受け入れ基準:**
- 部署マスタの CRUD はアプリ管理者が行う
- 部署には拠点（タイムゾーン）が紐づく
- 所属ユーザがいる部署は削除不可（先にユーザの所属変更が必要）

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| ユーザ規模 | 数万人 |
| レスポンスタイム | 95% のリクエストが 2 秒以内 |
| レスポンシブ | モバイル対応必須 |
| タイムゾーン | 拠点単位で可変 |
| セッション | 最終操作から 8 時間で失効 |
| 同時ログイン | 複数端末で許可 |
| アカウントロック | 5 回失敗で 30 分ロック |
| パスワード | 8 文字以上、英数字記号必須 |
| 監査ログ | 勤怠データの変更履歴を記録する（誰がいつ何を変更したか） |
| 可用性 SLA | 特に定めない |

---

## スコープ外

- 賃金計算（割増率の適用、給与計算）
- メール通知
- カレンダー形式の表示
- シフト管理
- 代理承認
- カレンダーの自動翌年コピー
